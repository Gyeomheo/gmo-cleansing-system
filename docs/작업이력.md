## 1. 현재 상태 (2026-10-23)

- 회차 실행 = 바탕화면 `Weekly Report` GUI **▶ 전체 실행** 한 번: ① 수집 · 클렌징 → ② 취합 검증 → ③ 취합본 → **③-2 처리 표시(`mark_done`) · 백과사전 STATUS(`status_check`)** → ④ 메일 본문. 기계 시간 약 2분(드라이런 110초)
  - CSV 를 직접 받은 경우는 예전처럼 `클렌징.cmd` 에 끌어다 놓기. 매핑 고칠 때만 `매핑등록.xlsx` O 표시 → `매핑등록.cmd`
- 마지막 회차: **W43 CE**(SEDA · SEI · SEPR · SETK · SIEL) — 취합본 v1(10/20), 처리 표시 · 클렌징본 8개 · STATUS 기재까지 끝(2026-10-23). 다음: **W44 MX**
- 사람 몫: ①② 메일 첨부를 국가별 weekly 폴더에 저장, 경고 확인, Gmail · CPCex 보내기, 리마인드(HTML [본문 복사]). 리마인드 자동 회신은 가안(§4)
- 클렌징 로직(`src/pipeline.py`)은 그대로. 기본 경로 결과는 자동화 전 `run.py` 와 **바이트 단위로 같음**(2026-10-20, 27개 CSV 대조)
- 마스터는 아직 지난 매핑 기준 행이 섞여 있다 → §4 첫 줄

## 3. 확정 규칙 · 알아 둘 것

- **미디어는 표준표만** — 표에 없으면 Others, 원본은 `Media Platform (Raw)` 에만. 미디어 매핑 엑셀에 새 플랫폼을 추가하지 않는다(담당자 2026-10-20)

- **기존 클렌징 로직 + 알파 (대체 아님)** — 담당자 확정 2026-10-20. `src/pipeline.py` 는 손대지 않는다(2026-10-20 기준 변경 0줄).
  추가 기능은 모두 그 위: 매핑 엑셀 행 추가 · 클렌징 뒤 캠페인 보정(빈 값 · Multi · Others 만) · 실행 전후 도구

- **입력 자리(슬롯) = (법인, MX/CE)**. `BU` 열이 있으면 CE — run.py 분기와 같은 기준. 같은 자리 파일이 두 개면 점검에서 멈춘다
- **Unmapped 리포트로는 신제품을 못 잡는다.** 파이프라인은 처음 보는 값도 분류 단위로 '구제'(예: `Z Fold9` → Smartphones / Multi,
  미디어는 원본 그대로)하면 리포트에 남기지 않는다. 그래서 `mapping.py propose` 는 원본에서 키 존재 여부를 직접 본다
- 키 비교 기준: MX · MEDIA 는 정규화 키를 대소문자까지 그대로(pd.merge), CE 는 소문자. 그래서 `Tab S10 Fe` 와 `Tab S10 FE` 는 MX 에서 다른 키
- 정규화(`fast_normalize_text`): 전부 대문자 · 소문자인 값은 Title Case(`S26 FE` → `S26 Fe`), camelCase 는 띄움(`TikTok` → `Tik Tok`)
- 마스터 갱신(`updater`)은 법인별로 **숫자(Spend · Revenue · Imp · Click · Order)가 처음 달라진 날**부터 교체한다. 분류만 바뀌면 교체 안 됨 → `--remap`
- 캠페인 규칙: 택소노미(`CN~…_PR~…_SB~…`)는 SETK · SEAU CE · SEPR 만. SEC · SEDA · SIEL 은 캠페인명이 자유 텍스트라 PR 규칙이 안 먹는다(키워드 규칙은 가능)
- cleaned 파일은 MX 에도 `BU` 열(MX)이 있다 — MX/CE 구분은 입력 파일 머리줄로 볼 것
- Excel COM 에 파이썬 datetime 을 넘기면 시간대 변환으로 9시간 당겨진다 → 날짜는 Excel 일련번호로 쓴다(tools/consolidate.py)
- 취합본 피벗은 캐시 1개를 같이 쓴다 — 캐시 원본 범위 직접 변경은 Excel 이 막고, 피벗마다 지정하면 캐시가 갈라져 파일이 커진다 → 새 캐시 하나 + CacheIndex 공유
- **처리 표시 · 클렌징본**(`mark_done`): collect 와 같은 선택 로직을 다시 돌려 '쓴 파일'을 정한다. 클렌징본은 `2_Output/cleaned_*` 의 행이 수집 표(2026 행)와
  순서대로 하나씩 맞아야 만든다(날짜 · Spend 대조). 그래서 **collect 는 XXX 파일을 건너뛰면 안 된다**(합치는 순서가 바뀜) — 허겸수정본만 건너뛴다.
  MMDD 비교 기준 = 수집 CSV 이후 첫 마스터 백업(= 그 회차 실행 직전). `collect.py` 를 미리보기로 다시 돌리면 수집 CSV 시각이 바뀌니 그땐 `--base` 로 지정
- **백과사전 Status Check**(`status_check`): 칸 = 폴더 날짜의 ISO 주차(CE `SEAU 1001` → W40). 빈 칸만 채움, 손 값과 다르면 그대로 두고 목록만.
  폴더 `SEBN` · `SECZ` = 시트 `SEBN_BE · SEBN_NL` / `SECZ_CZ · SECZ_SK` 둘 다. 이번 주 그 구분 입력이 없으면 정리 · 취합은 안 건드림
